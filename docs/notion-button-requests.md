# 노션 버튼·자동화 → `요청` 칸 (원본, 261123)

> 원본(하다 학원관리 v2.0)만. 학원 운영에는 아직 적용하지 않는다(옛 웹훅 경로 `notion-router`는 그대로 살아 있음).
> 앞 단계: [노션 웹훅 사본 반영](notion-webhook-sync.md) — 웹훅 구독 1곳(`notion-events`)이 켜져 있어야 한다.

## 무엇이 바뀌나

| | 예전 | 지금(원본) |
|-|-|-|
| 버튼 | "이 페이지 편집 `웹훅 버튼` = 동작 ID" → **웹훅 보내기**(주소·웹훅 키) | 같은 편집 단계에 `요청` = 동작 ID를 더하고 **웹훅 보내기 단계는 뺀다** |
| 자동화(⚪ 대기·삭제 체크 등) | 조건이 맞으면 **웹훅 보내기**(`웹훅 정보` 등) | 같은 조건에서 **이 페이지 편집 `요청` = 동작 ID** |
| 서버가 받는 곳 | 46곳 → `notion-router` | 웹훅 구독 1곳 → `notion-events` → 대기열 → 처리기 |
| 학원 배포 때 등록할 곳 | 버튼 20 + 자동화 26 = **46곳**에 주소·키 | 노션 연동 Webhooks 구독 **1곳** |

동작 ID와 함수는 예전과 같은 표(`supabase/functions/_shared/webhookRoutes.ts`, 46개)를 쓴다.

## 서버가 하는 일 (`_shared/notionRequests.ts`)

1. 웹훅 구독이 "이 줄이 바뀜"을 알린다 → 대기열(같은 줄은 2초 묶음) → 처리기가 그 줄을 다시 읽는다.
2. `요청`이 아는 동작 ID면 `요청` = `🔄 처리 중`, `요청 결과` = "🔄 처리 중 · 동작 이름 · 접수 시각".
3. 그 동작의 기존 함수로 넘긴다 — 길잡이와 같은 주소·같은 본문 모양(`{ data: 페이지 }`, 노션 자동화 웹훅과 같은 페이지 객체)·지금 서버 키. 함수의 잠금·상태·큐는 그대로다.
   - 요청 ID가 그 줄 `웹훅 정보` 수식에 들어 있으면 `웹훅 정보`의 ID를 모두 넘긴다(예전 자동화가 보내던 것과 같게).
4. 다시 읽어 `요청`이 아직 처리 중이면 `✅ 완료`(또는 `⚠️ 실패`), `요청 결과` = "✅ 완료 · 동작 이름 · 걸린 초 · 시각" / "⚠️ 실패 · 이유". 그 사이 새 요청이 들어왔으면 `요청`은 두고 `요청 결과`만 쓴다(새 요청은 대기열이 이어서 처리).
   - "완료" = 함수가 받았다는 뜻이다. 큐로 처리하는 함수(알림톡·보고서·수업 생성 등)의 실제 결과는 예전처럼 그 함수의 상태 칸(`보고서 전송 상태` 등)에 남는다.
   - 함수가 4xx로 답하면 실패 + 함수가 준 이유. 네트워크·5xx면 길잡이와 같은 "다시 넘기기"(sync_queue `notion-router-retry`, 최대 3번)에 넣고 그 사실을 적는다.
- **메아리**: 서버가 쓴 처리 중·완료·실패는 동작 ID가 아니라서 다시 읽어도 아무 일도 하지 않는다.
- **같은 줄 연속 누름**: 처리가 끝나 `요청`이 완료로 바뀐 뒤 다시 누르면 새 요청이다. 2초 안에 두 번 누르면 한 번으로 묶인다.
- **어느 DB를 읽나**: 사본이 없는 DB 이벤트는 원래 노션을 읽지 않는다. 데이터 소스마다 처음 한 번 읽어 `요청` 칸이 있는지 보고 표 `notion_request_sources`에 1시간 기억한다.
- `웹훅 버튼` 칸은 보지 않는다(옛 방식 버튼과 겹쳐 두 번 돌지 않게).

## 노션 칸 (DB마다 두 칸, 시스템 구역에 숨김)

- `요청` (select): 그 DB 동작 ID들 + `🔄 처리 중` · `✅ 완료` · `⚠️ 실패`
- `요청 결과` (텍스트)

## 되돌리는 법

- 버튼 하나: 편집 단계에서 `요청`을 빼고, 웹훅 보내기 단계를 다시 넣는다(주소 `…/functions/v1/notion-router`, 헤더 `x-admin-key` = 웹훅 키, 보낼 속성 `웹훅 버튼`).
- 자동화 하나: "`요청` = ID" 단계를 웹훅 보내기(같은 주소·키, 보낼 속성 `웹훅 정보` — 링크 2곳은 `웹훅 링크`, 수업 날짜 이동은 `웹훅 수업일시`)로 바꾼다.
- 서버 전체: 함수 설정 `NOTION_EVENTS_REQUESTS=off` → 요청을 넘기지 않는다(사본 반영은 그대로). 이때는 버튼을 옛 방식으로 되돌려야 동작한다.
