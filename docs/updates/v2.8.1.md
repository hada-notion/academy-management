- 상태: 원본 Notion 반영 2026-11-14. 서버 코드(항목 1)는 단위 테스트만 했고 실제 Notion에서 예시 데이터 비우기를 돌려 보지는 않았다. `docs/기준`의 지문·레이아웃·관계 문서는 이 버전에서 갱신하지 않았다(아래 "알려진 남은 것").
- 날짜: 2026-11-14
- 이전 버전: v2.8.0
- 요약: 교재 관련 DB 네 개의 제목을 쓰임새에 맞게 바꿨다(진도교재 → 진도관리, 교재배부 → 청구 항목, 교재비 → 청구, 교재결제 → 청구 결제). 새 시즌(학원) DB, 학년(학원) DB의 `사용`·`순서`·`N수` 줄, 청구 항목(학원) DB의 `종류`·`기타경비 항목`·`청구 월`, 라이브러리(학원) DB의 `기타경비 항목`을 더했다. **속성(칸) 이름은 하나도 바꾸지 않았다.** 예시 데이터 비우기는 새 이름과 옛 이름을 모두 알아본다.

## 운영 적용 순서 (한눈에)

원칙
- **코드가 먼저, 이름 바꾸기는 그다음.** 예시 데이터 비우기는 비울 DB를 Notion DB 제목으로 찾는다. 새 코드는 옛 이름·새 이름을 모두 알아보므로, 코드를 먼저 올리면 이름을 언제 바꿔도 된다. 순서를 뒤집으면 예시 데이터 비우기가 이름 바뀐 DB를 비우지 못한다(이미 쓰고 있는 학원은 이 기능이 잠겨 있어 다른 동작에는 영향이 없다).
- **속성(칸) 이름은 바꾸지 않는다.** 서버는 속성을 이름으로 찾는다. `진도교재`·`교재비`·`교재배부`·`교재결제` 관계, `배부일`, `교재비 수기입력`, `교재비 금액`, 버튼 [진도교재 담기] 같은 이름은 옛 낱말이 들어 있어도 그대로 둔다. 바꾸면 교재 생성·청구·알림톡이 멈춘다.
- **환경 변수는 그대로.** 서버는 DB를 환경 변수의 ID로 찾는다(`DATA_SOURCE_PROGRESS_BOOK_ID`·`DATA_SOURCE_TEXTBOOK_CART_ID`·`DATA_SOURCE_TEXTBOOK_DISTRIBUTION_ID`·`DATA_SOURCE_TEXTBOOK_PAYMENT_ID`). 제목을 바꿔도 ID는 같으므로 Secret을 고치지 않는다.
- **학원 Notion의 DB 제목 바꾸기와 DB·속성 추가는 그 학원 운영 소유자(원장님)의 승인 뒤에 한다**(AI·관리자 작업 규칙). 전체 계획을 한 번 승인받으면 아래 단계는 다시 묻지 않고 이어서 한다.
- 새 칸은 모두 기록용이다. 이 버전의 서버·수식·자동화는 새 칸과 시즌 DB를 읽지 않는다. 그래서 2~5단계는 서로 순서를 바꿔도 동작에는 차이가 없다.

## 항목 1. 예시 데이터 비우기가 바뀐 DB 이름과 시즌 DB를 알아봄

- **유형**: AI 자동
- **선행 조건**: 없음(가장 먼저 한다)
- **변경 이유·증상**: 예시 데이터 비우기는 비울 DB를 Notion DB 제목으로 찾는다. 제목을 바꾼 네 DB와 새 시즌 DB는 목록에 없어 비워지지 않고 "목록에 없는 DB"로 보였을 것이다.
- **대상 코드**: `supabase/functions/_shared/exampleClear.ts`, `scripts/clear-example-data.py`, 테스트 `supabase/functions/_shared/exampleClear_test.ts`를 원본 `main` 최신본으로 바꾼다.
  - 찾을 원문(앵커): `exampleClear.ts`의 `export const RENAMED_DBS`, `export function mergeRenamed`, `const OPTIONAL_DBS`.
- **동작**
  - 비울 DB 목록과 화면 묶음이 새 이름을 쓴다: "수업·학습"의 진도관리(학원) DB, "수납"의 청구(학원) DB·청구 항목(학원) DB·청구 결제(학원) DB.
  - 옛 이름 → 새 이름 표(`RENAMED_DBS`)가 있어, 아직 이름을 바꾸지 않은 학원의 옛 이름 DB도 같은 항목으로 비운다. 옛 이름과 새 이름이 함께 있어도 한 번만 세고, "목록에 없는 DB"나 "찾지 못한 DB"로 내지 않는다. 지난번에 "남기는 DB"로 적어 둔 옛 이름도 새 이름으로 읽는다.
  - 시즌(학원) DB를 "학생·수강" 묶음에서 시간표(학원) DB 다음에 비운다. 시즌 DB가 아직 없는 학원에는 "찾지 못한 DB" 안내를 내지 않는다.
  - PC 스크립트 `scripts/clear-example-data.py`도 같은 목록·같은 표다(테스트가 두 목록을 대조한다).
- **환경별 값·Secret**: 없음
- **Notion 변경**: 없음
- **마이그레이션 / 재배포**: 마이그레이션 없음. 함수 `clear-example-data`·`process-sync-queue` 재배포(원본 `main` 반영 시 배포 작업이 함께 올린다).
- **검증**: `deno test`의 `exampleClear_test.ts` 17개 통과(옛 이름만 있는 학원, 새 이름만 있는 학원, 둘이 섞인 경우, 시즌 DB가 없는 경우). **실제 Notion에서 예시 데이터 비우기를 돌려 보지는 않았다(미검증).** 이미 쓰고 있는 학원은 이 기능이 잠겨 있으므로 배포 뒤 확인할 화면이 없다. 새로 설치하는 학원은 [비울 데이터 확인]에서 네 DB와 시즌 DB가 묶음 안에 보이고 "목록에 없는 DB"에 없는지 본다.
- **실패 시 대처**: 세 파일을 이전 버전으로 되돌리고 두 함수를 재배포한다. 되돌린 동안에는 DB 제목을 바꾸지 않는다.
- **매뉴얼**: 변경 없음(화면 문구는 같다. DB 이름은 항목 6에서 함께 고친다).

## 항목 2. DB 제목·보기 탭·메뉴 이름 바꾸기

- **유형**: AI 자동(Notion 이름 바꾸기는 운영 소유자 확인 뒤)
- **선행 조건**: 항목 1 배포 완료
- **변경 이유**: 교재비만 청구하던 DB에 교습비·기타경비도 적을 수 있게 하면서(항목 5) 이름을 "청구"로 맞추고, 진도교재 DB는 "진도관리"로 부른다. 이름만 바뀌고 구조와 동작은 같다.
- **Notion 변경(최종 모양)**

  | 종류 | 바꾸기 전 | 바꾼 뒤 |
  | --- | --- | --- |
  | DB 제목 | 진도교재(학원) DB | 진도관리(학원) DB |
  | DB 제목 | 교재배부(학원) DB | 청구 항목(학원) DB |
  | DB 제목 | 교재비(학원) DB | 청구(학원) DB |
  | DB 제목 | 교재결제(학원) DB | 청구 결제(학원) DB |
  | 보기 탭(청구 항목 DB) | 교재배부 | 청구 항목 |
  | 보기 탭(청구 DB) | 교재비 | 청구 |
  | 보기 탭(청구 결제 DB) | 교재결제 | 청구 결제 |
  | 메뉴 페이지 이름 | 진도교재 | 진도관리 |
  | 공개 DB 페이지 묶음 제목 | 교재비 관리 | 청구 관리(설명 문장도 원본과 같게) |

  - DB 제목은 데이터베이스와 데이터 소스 두 곳 모두 바꾼다.
  - **그대로 두는 것**: 진도관리 DB의 보기 탭 `진도교재`와 제목 칸 이름 `진도교재`, 이름이 `진도교재`인 줄 하나, 모든 속성·버튼 이름(운영 적용 순서 원칙 둘째 줄), 메뉴 페이지의 보기 탭(`교재 배부(미납)` 등), 속성 설명 글 안의 옛 DB 이름.
  - 운영의 현재 이름이 "바꾸기 전"과도 "바꾼 뒤"와도 다르면 멈추고 [원본 요청](../기준/적용-절차.md#3-원본-요청-흐름)을 한다.
- **환경별 값·Secret**: 바꾸지 않는다. 서버는 DB를 환경 변수의 ID로 찾고 ID는 제목을 바꿔도 같다.
- **마이그레이션 / 재배포**: 없음
- **검증**: 네 DB 제목과 세 보기 탭이 표의 "바꾼 뒤"와 같다. 네 DB의 줄을 열었을 때 관계·롤업·수식 값이 바꾸기 전과 같다(DB 제목이 아니라 속성으로 이어져 있어 바뀌지 않아야 한다).
- **실패 시 대처**: 제목을 옛 이름으로 되돌린다(새 코드는 옛 이름도 알아본다).
- **매뉴얼**: 항목 6.

## 항목 3. 시즌(학원) DB

- **유형**: AI 자동(DB·칸·보기) + 운영자 직접(DB 아이콘)
- **선행 조건**: 항목 1 배포 완료(새로 설치하는 학원이 예시 데이터를 비울 때 시즌 DB도 비워지도록)
- **변경 이유**: 시간표를 기간(시즌)별로 묶는 상위 DB다. 준비 중인 관리 앱이 쓸 예정이고, 이 버전에서는 자동화·수식·서버 어느 것도 읽지 않는다.
- **Notion 변경(최종 모양)**
  - 항목: `시즌(학원) DB`(새 DB). 위치는 공개 DB 페이지 "클래스·시간표" 묶음 안, 시간표(학원) DB 다음.

    | 속성 | 타입 | 값 |
    | --- | --- | --- |
    | `이름` | 제목 | |
    | `기간` | 날짜(범위) | |
    | `상태` | 선택 | 준비 중 / 운영 중 / 끝남 |
    | `시간표` | 관계 → 시간표(학원) DB, 양방향 | 시간표 쪽 이름 `시즌` |

  - 보기: 이름 "시즌"(새로 만들면 "Default view"로 생기므로 이름을 바꾼다).
  - 항목: `시간표(학원) DB / 속성 / 시즌` — 위 관계의 짝. 레이아웃은 제목 아래 고정 칸에서 `클래스` 다음. "시간표" 보기에 `시즌` 열.
  - "클래스·시간표" 묶음 설명 문장에 시즌을 더한다(원본과 같게).
  - 이미 있으면 건너뛴다. 칸 이름이 다르면 멈추고 원본 요청.
  - 줄은 만들지 않는다(비워 둔다). 시간표의 `시즌`도 비워 둔다.
- **운영자 안내문(DB 아이콘)**
  - 왜 필요한가: 다른 DB와 같은 모양으로 보이게 한다. 도구로는 넣을 수 없어 화면에서 직접 한다.
  - 어디서: Notion > 공개 DB 페이지 > "클래스·시간표" 묶음 > 시즌(학원) DB를 전체 페이지로 연다.
  - 무엇을: 1. 제목 왼쪽의 아이콘 자리를 누른다. 2. 같은 묶음의 시간표 DB와 어울리는 아이콘을 고른다.
  - 끝났는지 확인하는 방법: 공개 DB 페이지 목록에서 시즌 DB 앞에 아이콘이 보인다.
  - 흔한 오류와 대처: 아이콘이 없어도 동작에는 영향이 없다. 나중에 해도 된다.
- **마이그레이션 / 재배포**: 없음
- **검증**: 시즌 DB에 네 칸이 있고, 시간표 줄 하나를 열면 제목 아래에 `시즌`이 보인다.
- **실패 시 대처**: 시즌 DB와 시간표 `시즌` 칸을 지운다(비어 있을 때만). 서버는 이 DB를 읽지 않는다.
- **매뉴얼**: 항목 6.

## 항목 4. 학년(학원) DB: `사용`·`순서`, `N수` 줄

- **유형**: AI 자동
- **선행 조건**: 없음
- **변경 이유**: 학원이 받지 않는 학년의 줄을 지우면 그 학년에 연결된 과목 등의 연결이 함께 끊긴다. 줄은 두고 `사용` 체크로 끄게 한다(설치 때 "안 받는 학년 줄 삭제"를 대신한다). `순서`는 4세부터 N수까지 학년 순으로 보이게 한다.
- **Notion 변경(최종 모양)**
  - 항목: `학년(학원) DB / 속성 / 사용` — 체크박스. 설명: 체크한 학년만 관리 앱 학년 목록에 보인다. 안 받는 학년은 줄을 지우지 말고 체크를 끈다. **추가한 뒤 지금 있는 줄을 모두 체크한다**(새 체크박스는 꺼진 채로 생긴다).
  - 항목: `학년(학원) DB / 속성 / 순서` — 숫자. 값:

    | 학년 | 순서 | 학년 | 순서 | 학년 | 순서 | 학년 | 순서 |
    | --- | --- | --- | --- | --- | --- | --- | --- |
    | 4세 | 1 | 초1 | 5 | 중1 | 11 | 고1 | 14 |
    | 5세 | 2 | 초2 | 6 | 중2 | 12 | 고2 | 15 |
    | 6세 | 3 | 초3 | 7 | 중3 | 13 | 고3 | 16 |
    | 7세 | 4 | 초4 | 8 | | | N수 | 17 |
    | | | 초5 | 9 | | | | |
    | | | 초6 | 10 | | | | |

  - 항목: `학년(학원) DB / 보기 / 학년` — 정렬을 `순서` 오름차순 하나로(바꾸기 전: `학교구분` 내림차순 + `이름` 오름차순). `사용`·`순서` 열을 보이게 한다.
  - 새 줄 `N수`(**재수·N수 학생을 받는 학원만**): `학교구분` 🟤 고등학교, `사용` 체크, `순서` 17, 페이지 아이콘 🟤. 받지 않는 학원은 만들지 않는다.
  - 학원이 이미 학년 줄을 지웠다면 되살리지 않는다. 있는 줄에만 `사용` 체크와 `순서`를 넣는다(순서 값은 위 표 그대로, 중간이 비어도 된다).
  - 이미 받지 않는 학년이 있다고 원장님이 알려 주면 그 줄만 `사용`을 끈다. 운영 AI가 짐작으로 끄지 않는다.
- **동작 확인(원본)**: 학교 학사일정 가져오기는 학년을 `학교구분`과 이름 끝의 숫자로 찾는다. `N수`는 끝에 숫자가 없어 걸리지 않으므로 고등학교 학사일정이 N수 줄에 잘못 붙지 않는다(코드 확인). 예시 데이터 비우기는 학년 DB를 남긴다. 이 버전의 서버·수식은 `사용`·`순서`를 읽지 않는다.
- **마이그레이션 / 재배포**: 없음
- **검증**: "학년" 보기가 4세 → … → 고3 → N수 순서이고 모든 줄의 `사용`이 체크돼 있다.
- **실패 시 대처**: 두 칸을 지우고 보기 정렬을 바꾸기 전으로 되돌린다. N수 줄은 학생·과목이 연결되지 않았을 때만 지운다.
- **매뉴얼**: 항목 6.

## 항목 5. 청구 항목(학원) DB `종류`·`기타경비 항목`·`청구 월`, 라이브러리(학원) DB `기타경비 항목`

## 항목 7. 메뉴 재구성: 분류 이름, 교재비 메뉴, 청구 보기 탭, 손익 분석 이번 달 지출, 비용 자리

- **유형**: AI 자동(페이지 이름·본문·보기 추가·복제·분류 이동, API) + 운영자 직접(분류 선택지 이름, 보기 탭 삭제, 필터의 "이번 달" — 도구로 못 하는 화면 작업)

- **변경 이유**: 청구(학원) DB가 교재비·재료비·기타경비를 함께 담게 되면서, 교재와 함께 다루는 교재비·재료비는 교재 묶음에, 그 밖의 기타경비와 모든 청구 줄은 재무 묶음에 두었다. 손익 분석 페이지에서 그 달 지출을 바로 보게 했고(손익 = 매출 − 지출의 지출 쪽), 거의 쓰지 않는 비용 페이지는 자료·데이터로 옮겼다. 수강료 메뉴는 이름·탭 모두 그대로다. 분류 이름은 짧게 맞췄다.
- **Notion 변경(최종 모양)**

  - 메뉴 페이지 `비용`: `분류` = `9. 자료·데이터`, `순서` = 95. 본문은 그대로.
  - 새 메뉴 페이지 **`교재비`**: 청구 페이지를 복제해 만든다. `분류` = `6. 교재`, `순서` = 63, 아이콘 태그(분홍), 커버는 원래 교재비 관리 커버. 보기 탭은 **클래스 · 교재비(미납) · 교재비(결제완료) · 재료비 · 결제**만 남긴다(청구·기타경비·전체 줄 탭 삭제). 안내 콜아웃: "학생별 교재비·재료비 청구와 결제 현황을 관리합니다. 피복비·모의고사비 같은 그 밖의 기타경비는 7. 재무 › 청구에서 봅니다." 콜아웃 제목 "📘 교재비". 복제한 블록이 원래 네 DB(클래스·청구·청구 항목·청구 결제)를 그대로 가리키는지 확인한다.

- **매뉴얼**: 항목 6(메뉴 경로 글).

## 항목 6. 매뉴얼 갱신

- **유형**: AI 자동(운영 매뉴얼 페이지 수정은 운영 소유자 승인 후, 16-8 9번)
- **대상**: 원본 매뉴얼에서 DB 이름으로 쓴 `진도교재(학원) DB`·`교재배부(학원) DB`·`교재비(학원) DB`·`교재결제(학원) DB`를 새 이름으로 바꾸고, 시즌(학원) DB, 학년 `사용`·`순서`·N수, 청구 항목 `종류`·`기타경비 항목`·`청구 월`, 라이브러리 `기타경비 항목`을 주요 데이터베이스 표·관계 표·구조도와 해당 장에 넣는다. **원본 매뉴얼은 2026-11-14에 7쪽을 반영했다**: 7-1 진도교재 준비, 7-1-1 그룹 진도(동기화 블록 원본), 3. 주요 데이터베이스 이해하기(학년 줄, 시간표 줄, 새 시즌 줄), 4-1-2 학년(`사용`·`순서`·N수 세 줄), 10-3 교재비(새 DB 이름, 청구 항목·라이브러리 새 칸 두 줄), 10-2-1 교습비 목록(새 칸은 아직 계산에 안 쓰인다는 한 줄), 17. 구조도(mermaid DB 상자 이름과 시즌 상자). 반영 뒤 다시 읽어 원문과 대조했다. 항목 7에 따라 4주차 목요일 교재비 할 일 링크를 새 교재비 메뉴로 바꿨다. "기타 설정·수강관리·교재관리"를 메뉴 경로로 쓴 문장은 매뉴얼에 없었다. 속성·버튼 이름으로 쓴 `진도교재`·`교재비` 등은 바꾸지 않는다.
- **운영 적용 방법**: v2.8.0과 같이 운영 매뉴얼을 원본 매뉴얼로 통째 교체한다(v2.8.0 셋째 표 7단계). 절만 골라 옮기지 않는다.
- **찾을 문구가 없을 때**: 그 문단만 보류하고 기록한다. 위치를 추정해 새로 넣지 않는다.
- **검증**: 교체 뒤 운영 매뉴얼에서 옛 DB 이름 네 개를 찾아 DB 이름으로 쓴 곳이 남지 않았는지 본다(속성·버튼 이름으로 쓴 곳은 남는 것이 맞다).

## 부록. 바꾸기 전 원문 (운영 대조용)

운영의 현재 값이 아래 "바꾸기 전"과 다르면 멈추고 원본 요청을 한다. 원본에서 2026-11-14에 기록한 값이다.

### DB 제목·보기 탭·메뉴 이름 — 바꾸기 전 (항목 2)
- DB 제목: 진도교재(학원) DB, 교재배부(학원) DB, 교재비(학원) DB, 교재결제(학원) DB.
- 보기 탭: 교재배부 DB `교재배부`, 교재비 DB `교재비`, 교재결제 DB `교재결제`.
- 메뉴 페이지 이름: `진도교재`.
- 공개 DB 페이지 묶음 제목: "교재비 관리".

### 시간표(학원) DB — 바꾸기 전 (항목 3)
- `시즌` 칸 없음. 제목 아래 고정 칸은 `클래스`까지, "시간표" 보기에 `시즌` 열 없음.

### 학년(학원) DB — 바꾸기 전 (항목 4)
- 속성 `사용`·`순서` 없음. 줄 16개(4세~7세, 초1~초6, 중1~중3, 고1~고3), `N수` 없음.
- "학년" 보기 정렬: `학교구분` 내림차순 + `이름` 오름차순.

### 청구 항목(옛 교재배부)·라이브러리 — 바꾸기 전 (항목 5)
- 교재배부(학원) DB: `종류`·`기타경비 항목`·`청구 월` 없음. 제목 아래 고정 칸은 `결제 상태`까지.
- 라이브러리(학원) DB: `기타경비 항목` 없음.

### 메뉴 재구성 — 바꾸기 전 (항목 7)
- `분류` 선택지: 1. 운영 / 2. 수업 / 3. 학생 / 4. 학교 / 5. 수강관리 / 6. 교재관리 / 7. 재무 / 8. 기타 설정 / 9. 자료·데이터.
- 7. 재무: 수강료(71) · 청구(71.5) · 비용(72) · 손익 분석(73). 6. 교재관리: 라이브러리(61) · 진도관리(62).
- 손익 분석 페이지: 보기 탭에 `이번 달 지출` 없음. 안내 콜아웃: "학원 전체 매출.지출, 손익을 월별로 확인합니다."
- 청구 페이지 보기 탭: 클래스 · 청구 · 교재비(미납) · 교재비(결제완료) · 재료비 · 기타경비 · 전체 줄 · 결제. 안내 콜아웃: "학생별 교재비·재료비·기타경비 청구와 결제 현황을 관리합니다. 매달 내는 수강료는 수강료 메뉴에서 봅니다."

### 작업 중 생긴 실수와 최종 반영 (반복하지 않기)

- 처음에는 지출내역을 수강료 페이지에 넣고 이름을 `수강료·지출`로 바꿨다 → 수강료 페이지는 수강료 작업이 대부분이라 이름이 흐려지고, 지출은 손익을 볼 때 필요해 손익 분석 페이지로 옮기고 수강료 이름을 되돌렸다(운영에 적용하지 않음). 매뉴얼에서 고쳤던 "수강료·지출" 글도 원래대로 되돌렸다.

- DB 제목을 먼저 바꾼 뒤에야 예시 데이터 비우기가 DB를 제목으로 찾는다는 것을 확인했다 → 코드에 옛 이름 → 새 이름 표를 넣고, 운영은 코드를 먼저 올리게 했다(운영 적용 순서 1단계). DB 제목을 바꾸기 전에 제목으로 찾는 코드가 있는지 먼저 찾는다.
- 새 DB(시즌)가 공개 DB 페이지 맨 아래에 생겼다 → "클래스·시간표" 묶음 안 시간표 DB 다음으로 옮겼다. 새 DB는 만들 때 놓을 묶음을 정한다.
- 새 DB의 보기 이름이 "Default view"로 남았다 → "시즌"으로 바꿨다.
- API로 더한 새 칸(청구 항목 `종류`·`기타경비 항목`·`청구 월`, 시간표 `시즌`, 학년 `사용`, 라이브러리 `기타경비 항목`)이 페이지에서 숨은 자리에 들어가 보이지 않았다 → 칸을 더한 뒤 레이아웃(제목 아래 고정·패널 구역)과 보기 열을 함께 맞춘다(항목 3~5의 레이아웃 줄).
- 학년 보기가 `학교구분`·`이름` 정렬이라 새 `N수` 줄이 학년 순서와 다른 자리에 보였다 → 숫자 `순서`를 더하고 그 칸으로 정렬했다.
- 새 체크박스 `사용`은 꺼진 채로 생긴다 → 추가한 바로 다음에 있던 줄을 모두 체크했다(항목 4).
