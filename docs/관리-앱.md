# 관리 앱

> 운영 AI가 이 학원의 관리 앱을 이해하고 어디부터 읽을지 알기 위한 한 장. 현재 구조의 기준이다.

## 정의

- 관리 앱은 **노션을 돕는 웹앱**이다. 서버 데이터를 대신 보여 주고, 시간표 입력처럼 노션으로 하기 불편한 일을 쉽게 하게 한다(대표 261119, v2.8.0 항목 97).
- 노션을 대체하지 않는다. **원본은 늘 노션**이고, 앱과 노션이 다르면 노션이 맞다.

## 위치와 배포

- 저장소 `prototype/admin-app/hada-admin.html`. 원본 `main`에서 GitHub Pages가 빌드한다.
- 각 학원은 자기 저장소의 Pages 주소로 연다.

## 연결 구조

- 앱 → 서버(Edge Function `app-api`: `list` · `save` · `run` · `options`, 상태 확인용 `status`) → Supabase 사본(`app_rows`) → 노션.
- 읽기는 사본에서 한다. 쓰기는 노션에 먼저 쓴 뒤 사본에 반영한다. 노션에서 직접 고친 값은 정기 동기화로 사본에 온다(5분 간격, 최대 약 5~7분 늦음).
- 수업 쪽(출결 · 보강 · 학습기록 · 루틴 체크 등)은 수업 관리 함수 `class-room`을 부른다(`livelesson.js`).
- 자세한 동작은 v2.8.0 항목 74(읽기 사본) · 75(저장) · 76(실행) · 91(시험 저장) · 96(루틴).

## 로그인

- 관리자 세션(키오스크 · 법정 서류 · 수업 관리와 같은 관리자 비밀번호, 세션 12시간).
- 첫 설치의 초기 비밀번호(`0000`)로 로그인하면 로그인 창이 바로 새 비밀번호를 정하게 한다(서버 `admin-security` 설정용 로그인 → `change`). 그 창의 "설치하는 중이면 — 예시 데이터 먼저 비우기"로 비밀번호를 바꾸지 않고 예시 데이터를 비울 수 있다 — `0000`으로는 고르기 없이 비울 DB 전부(남기는 DB는 그대로), 한 번 끝나면 잠김. `0000` 세션으로 서버가 받는 것은 `clear-example-data`와 비밀번호 바꾸기뿐(`_shared/adminSecurity.ts` `authorizeInitialSetup`). 설치 순서: `0000` → 전체 비우기 → 잠김 → `0000` 그대로 넘김 → 원장 첫 로그인에서 비밀번호.
- 관리자 비밀번호 바꾸기 · 예시 데이터 비우기 · 노션 연동 구독 상태는 관리 앱 [관리자 설정], 책 찾기(국립중앙도서관 · 교보문고) · 단원 고치기 · 시리즈 관리는 [라이브러리]에서 한다. 나이스 학교 검색 · 학교 추가 · 학교 코드 연결 · 학사일정 가져오기는 [학교]에서 한다(서버 `school-api` · `sync-school-calendar`, 노션 학교 페이지의 [학교 검색] 링크도 이 앱의 학교 화면을 연다). 옛 관리자 설정 · 라이브러리 · 학교 검색 웹 화면은 없앴다(v2.8.0).
- 웹훅 키 교체 화면은 없다 — 원본은 노션 연동 구독 방식이라 웹훅 키를 쓰지 않는다. 옛 버튼 방식(웹훅 키) 학원은 구독 방식으로 바꾼 뒤 이 판을 받는다(`docs/updates/v2.8.0.md` 운영 적용 순서).

## 쓰기 스위치

- 한 곳: `prototype/admin-app/hada-rules.js`의 `GATES_ON`. 실제 자료 모드에서 꺼진 칸의 화면은 메뉴에서 빠진다.
- 현재 켜짐: P1(입력) · P2(보기) · P3(수업 보기) · P2e(일정 쓰기) · P3b(학습기록 · 루틴 쓰기) · P3w(출결 쓰기).
- 꺼짐: P3m(보강 쓰기 — 끌어놓기 화면을 사람이 확인한 뒤 켠다), P6(옛 HTML 흡수).
- 주소에 `&gates=…`를 붙이면 병합 전에 시험용으로 켤 수 있다.
- 시험 · 재무 · 법정 서류 화면은 보기 전용이다. 알림톡 · 학부모 메시지 전송은 앱에서 하지 않고 노션 버튼으로 한다.

## 라이브러리(교재) 입력

- 호출 머리글은 `app-api`와 같다(`x-admin-key`=관리자 세션, `Authorization`·`apikey`=anon 키). 오류는 `{ error }` + HTTP 상태, 모든 요청은 POST.
- **새 교재**: `POST /functions/v1/textbook-api` `{ action: "register-custom", title, isbn13?, cover?(https), price?, pages?, series?, publisher?, units: [{ name, page }] }` → 교재 1권 + 단원목록을 노션에 만들고 라이브러리 복사본에 반영한다. 같은 ISBN13이면 409 "이미 라이브러리에 있는 교재입니다". 시리즈·출판사는 `series`/`publisher` 선택지에 있는 값만. 목차를 붙여 넣으려면 먼저 `{ action: "parse", text }`로 단원 후보를 받는다.
- **새 프로그램**(예체능, [프로그램] 탭의 [+]): 같은 `register-custom`에 `kind: "프로그램"`을 더한다 — `{ action: "register-custom", kind: "프로그램", title, price?(재료비), pages?(총 차시), cover?, series?, publisher?, units?: [{ name }](차시 목록, 생략·빈 목록 가능) }`. 라이브러리 줄의 `구분`을 프로그램으로 만들고, ISBN13은 안 받아도 된다. `kind`를 생략하면(또는 `"교재"`) 교재(`구분` 칸을 보내지 않음). 그 밖 값은 400 "구분은 교재 또는 프로그램이어야 합니다.", 이름이 비면 400 "프로그램 이름을 입력하세요.". 응답은 교재와 같고 `kind`가 추가된다(`{ ok, pageId, name, kind, units, … }`). 프로그램 줄의 칸 의미: `가격`=재료비, `전체 분량`=총 차시.
- **교재 고치기**: `POST app-api` `{ action: "save", changes: [{ op: "update", db: "라이브러리(학원) DB", id, edited, props }] }` — 칸은 이름 · 과목 · 구분 · 시리즈 · 교재 유형 · 교육과정 · 출판사 · 전체 분량 · 진도 단위 · 가격 · 사용중 · ISBN13 · 기타경비 항목(`appsave.js` books). 끝나면 라이브러리 복사본도 바로 맞춘다. `save`로 새 줄(create)을 보내면 400 "교재 추가는 라이브러리 등록(textbook-api register-custom)으로 하세요".
- 표지·시리즈·출판사만 바꿀 때는 `textbook-api` `set-book`도 같은 결과다. 단원 수정은 `edit-units`.
- 앱 쪽: `appsave.js`의 `APPS_OFF`·`live.js`의 보기만 목록(`books`)에서 books를 빼면 [+]는 새 교재 등록 창(`register-custom`), 연필은 `save`로 연결한다.

## 저장(save) 규약: 만들기 · 고치기 · 지우기

- `POST app-api` `{ action: "save", changes: [...] }`(한 번에 60줄까지). 줄마다 따로 성공·실패, 응답 `{ ok, results: [{ i, ok, id?, row?, error?, conflict?, deleted?, blocked? }] }`. 전부 성공이면 `ok: true` — 이때 사본(`app_rows`)은 노션과 같다(만들기·고치기는 노션 응답을 사본에, 지우기는 사본 줄을 바로 뺌).
- 지우기: `{ op: "delete", db, id, edited? }`(`props` 없음). 노션 휴지통으로 보내므로 복구할 수 있다. 성공 `{ ok: true, id, deleted: true }`. 이미 휴지통인 줄은 사본만 맞추고 성공.
- 지우기를 받는 DB: **시간표만**(구조 줄). 특별한 이유가 없으면 지우지 않는다(대표 261119) — 학생 · 등록 · 클래스 · 강사 · 과목 · 영역 · 진도관리 · 시즌과 그 밖 DB는 요청 검사에서 HTTP 400 `{ error: "삭제하지 않아요 — 종료·보류로 처리해요" }`(앱은 이 문구를 그대로 보여 주고, 종료·보류 칸으로 처리하게 안내한다. 단순 실수면 이름에 "실수"라고 적는다).
- 연결된 기록이 있으면 지우지 않는다: `{ ok: false, blocked: { "등록": 2 }, error: "연결된 기록이 있어 지우지 않았어요(등록 2건). 노션에서 먼저 정리하세요." }`. 막는 관계는 `appSave.ts`의 `DELETE_BLOCKERS`.
- 그 밖 오류: `conflict: true`(그사이 노션에서 바뀜, 다시 불러온 뒤), "이 DB의 줄이 아닙니다.", 노션 쓰기 실패 문구. 앱은 줄마다 `ok`를 보고 실패한 줄은 화면에 남겨 이유를 보여 준다. 503 `{ busy: true }`는 기존대로 한 번 다시 시도.
- 앱 쪽: `appsave.js`가 지금은 `dels`를 보내지 않는다(`row.del` 줄) — 허용 DB의 `del` 줄을 `op: "delete"`로 보내고, 성공한 줄만 화면·`DB`에서 빼면 된다(`?v=` 올림).

## [동기화](노션 → 사본)

- `POST app-api` `{ action: "run", name: "sync-copy", dbs?: [DB 이름…], full?: true }`(관리자 세션, 다른 `run`과 같은 머리글). `dbs`를 주면 그 DB만(화면에 쓰는 DB 목록), 생략하면 앱 DB 전체. 바뀐 줄만 사본에 넣는다.
- 응답 `{ ok: true, changed, deleted, ms, syncedAt, notFilled: [처음 채우기가 안 끝나 건너뛴 DB], problems: {DB: 이유}, results }`. 끝나면 앱이 `list`(필요하면 `since`)로 다시 읽고 `syncedAt`으로 "마지막 동기화 HH:MM"을 보인다.
- 노션에서 **지운** 줄은 바뀐 줄 동기화에 안 잡힌다. 지운 줄까지 맞추려면 `full: true` + `dbs` 1~3개(통째로 대조, 오래 걸림). 그 밖은 밤 대조가 맞춘다.
- `{ action: "status" }` 응답에 `syncedAt`(DB 커서 중 가장 늦은 시각)이 추가됐다. 오류는 `{ error }` + 400(`dbs` 형식·`full` 조건), 503 `{ busy: true, retryAfterSec }`는 기존 재시도 규약.
- 자동 5분 동기화(`app-copy-incremental`)는 비아 처음 채우기와 앱 [동기화] 배포가 끝난 뒤 별도 마이그레이션으로 끈다.

## 시스템 타이틀

- `POST app-api` `{ action: "status" }` 응답의 `rootTitle`(문자열 또는 `null`)은 노션 최상위 페이지(워크스페이스 바로 아래, 등록 DB 기준) 제목이다. 서버가 30분 기억하고 못 읽으면 `null`. 앱은 값이 있으면 사이드바 제목과 탭 제목 "관리 앱 | `rootTitle`"에 쓰고, 없으면 "하다 학원관리 v2.0" 그대로 둔다(예시 자료 모드는 서버를 부르지 않아 변화 없음).

## 학원마다 바꾸는 값(이름만)

- `hada_config.js`: `supabaseUrl`, `supabaseAnonKey`(브라우저에 공개되는 값). 원본 값을 복사하지 않고 `<이 학원 프로젝트>` 것으로 넣는다.
- 서버 설정: `ADMIN_ALLOWED_ORIGINS`(이 학원 Pages origin), `SITE_BASE_URL`(저장소 경로까지). 그 밖은 `docs/새-학원-이식-체크리스트.md`를 따른다.
