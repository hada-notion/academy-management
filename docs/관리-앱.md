# 관리 앱

> 운영 AI가 이 학원의 관리 앱을 이해하고 어디부터 읽을지 알기 위한 한 장. 현재 구조의 기준이다.

## 정의

- 관리 앱은 **노션을 돕는 웹앱**이다. 서버 데이터를 대신 보여 주고, 시간표 입력처럼 노션으로 하기 불편한 일을 쉽게 하게 한다(대표 261119, v2.8.0 항목 97).
- 노션을 대체하지 않는다. **원본은 늘 노션**이고, 앱과 노션이 다르면 노션이 맞다.

## 위치와 배포

- 저장소 `prototype/admin-app/hada-admin.html`. 원본 `main`에서 GitHub Pages가 빌드한다.
- 각 학원은 자기 저장소의 Pages 주소로 연다.

## 연결 구조

- 앱 → 서버(Edge Function `app-api`: `list` · `save` · `run` · `options`, 상태 확인용 `status`) → Supabase 사본(`app_rows`) → 노션.
- 읽기는 사본에서 한다. 쓰기는 노션에 먼저 쓴 뒤 사본에 반영한다. 노션에서 직접 고친 값은 정기 동기화로 사본에 온다(5분 간격, 최대 약 5~7분 늦음).
- 수업 쪽(출결 · 보강 · 학습기록 · 루틴 체크 등)은 수업 관리 함수 `class-room`을 부른다(`livelesson.js`).
- 자세한 동작은 v2.8.0 항목 74(읽기 사본) · 75(저장) · 76(실행) · 91(시험 저장) · 96(루틴).

## 모드(실제 자료 / 예시 자료)

판정은 `prototype/admin-app/live.js`의 `liveModeFor` 한 곳이다.

| 열기 | 모드 |
| --- | --- |
| 배포 사이트, 주소에 매개변수 없음 | 실제 자료(관리자 로그인 필요, 로그인 창에 [예시 자료로 보기]) |
| `?demo=1` 또는 `?live=0` | 예시 자료(내장 가짜 데이터, 서버를 부르지 않음) |
| `localhost` · `127.0.0.1` · `file:`로 열기 | 기본이 예시 자료 |
| `?live=1` | 실제 자료 |

## 로그인

- 관리자 세션(관리자 설정 사이트와 같은 계정 체계, 세션 12시간).
- 비밀번호와 웹훅 키 변경은 관리 앱이 아니라 관리자 설정 사이트(`admin_settings.html`)에서만 한다.

## 쓰기 스위치

- 한 곳: `prototype/admin-app/hada-rules.js`의 `GATES_ON`. 실제 자료 모드에서 꺼진 칸의 화면은 메뉴에서 빠진다.
- 현재 켜짐: P1(입력) · P2(보기) · P3(수업 보기) · P2e(일정 쓰기) · P3b(학습기록 · 루틴 쓰기) · P3w(출결 쓰기).
- 꺼짐: P3m(보강 쓰기 — 끌어놓기 화면을 사람이 확인한 뒤 켠다), P6(옛 HTML 흡수).
- 주소에 `&gates=…`를 붙이면 병합 전에 시험용으로 켤 수 있다.
- 시험 · 재무 · 법정 서류 화면은 보기 전용이다. 알림톡 · 학부모 메시지 전송은 앱에서 하지 않고 노션 버튼으로 한다.

## 코드를 바꿀 때

- `prototype/admin-app`의 js·css를 바꾸는 PR은 `hada-admin.html`의 `?v=` 번호를 올려야 한다(CI `tests/admin-app-version.cjs`가 확인).
- 화면 규칙은 `prototype/admin-app/관리앱-기준.md`, 디자인은 `docs/DESIGN.md`.

## 학원마다 바꾸는 값(이름만)

- `hada_config.js`: `supabaseUrl`, `supabaseAnonKey`(브라우저에 공개되는 값). 원본 값을 복사하지 않고 `<이 학원 프로젝트>` 것으로 넣는다.
- 서버 설정: `ADMIN_ALLOWED_ORIGINS`(이 학원 Pages origin), `SITE_BASE_URL`(저장소 경로까지). 그 밖은 `docs/새-학원-이식-체크리스트.md`를 따른다.
