# 관리 앱 열린 화면 자동 갱신 · 노션 요청 상태 (원본, 261123)

> 원본만. 학원 운영 적용은 따로 지침과 함께. 앞 단계: [노션 웹훅 사본 반영](notion-webhook-sync.md), [노션 버튼·자동화 → 요청 칸](notion-button-requests.md).

## 흐름

1. 노션에서 고침 → 웹훅(`notion-events`) → 약 5초 안에 서버 사본(`app_rows` · `cr_*`)이 바뀐다.
2. 사본 표의 문장 트리거가 **값이 실제로 바뀐 줄만** 세어 Supabase Realtime 공개 채널 `hada-app`에 신호를 보낸다(`realtime.send`).
   - `rows` = `{ dbs: [DB 이름…], n: 줄 수 }`, `cr` = `{ cr: 표 이름, n }`. 값 · 줄 id · 개인정보는 싣지 않는다.
   - 같은 값을 다시 쓰는 것(5분 사본 · 밤 대조)은 신호가 없다. 신호가 실패해도 사본 쓰기는 막지 않는다.
   - 사본에서 지운 줄은 `app_row_gone`에 남는다(3일 지난 기록은 트리거가 정리).
3. 열린 관리 앱(`prototype/admin-app/liverefresh.js`)이 신호를 받으면 0.6초 모아 app-api `{ action: "changes", since, dbs }`를 부른다(관리자 세션, 노션은 안 부름).
   - 서버(`_shared/appChanges.ts`)는 `since` 15초 앞부터 바뀐 줄 · 지운 줄을 준다. 500줄이 넘으면 `many` → 앱은 작성 중이 없을 때 전체를 다시 받는다.
4. 앱은 받은 줄을 원자료에 넣고 다시 계산해 **이전 계산과 달라진 줄만** 화면에서 바꾼다(표 줄 잠깐 파란 강조, 토스트 "노션에서 바뀐 n줄을 화면에 반영했어요").
   - 저장 안 한 줄(작성 중 · 지움 표시)은 덮지 않는다 → 창 위 "노션에서 이 줄이 바뀌었어요 — 지금 저장하면 내 값으로 덮어써요 [노션 값 불러오기]".
   - 입력 칸에 커서가 있거나 대화상자 · 저장 · 동기화 중이면 끝날 때까지 미룬다.
   - 수업 사본(`cr_*`)이 바뀌면 수업 · 오늘 · 보강 화면은 수업에 작성 중이 없을 때 그 기간 수업을 다시 받는다.
5. 안전망: 신호가 끊기면 60초마다(붙어 있으면 5분마다) 같은 `changes`로 따라잡고, 2초 → 30초 간격으로 다시 붙는다. 창을 다시 보면 바로 한 번 따라잡는다. [동기화] 단추는 그대로.

위 줄 [동기화] 왼쪽 점: 초록 = 신호 연결됨(몇 초 안), 회색 = 다시 연결하는 중(1분마다 확인).

## 노션 요청 상태

노션 자동화 17곳이 쓰는 `요청` · `요청 결과` 칸과 요청 줄 길(버튼 20 · 자동화 9)이 대상 줄에 쓰는 같은 두 칸(사본에 들어 있음)을 읽는다.
| `요청` 값 | 앱 표시 |
|-|-|
| 동작 ID(서버가 아직 안 받음) | 대기(5분 넘으면 "오래 걸려요") |
| 🔄 처리 중 | 처리 중(5분 넘으면 "오래 걸려요") |
| ✅ 완료 | 창 위에 10분 동안만 |
| ⚠️ 실패 | 실패 + `요청 결과`의 이유 |

- 표 줄: 대기 · 처리 중 · 실패 알약. 창 위: 상태 + 결과 글 + 시각.
- 홈 입력 점검: "노션 요청 실패" · "오래 걸리는 요청" 줄 → 누르면 목록(DB · 줄 이름 · 이유 · [노션에서 열기]).
- 홈 입력 점검 "노션 연동 구독 끊김"(261123): `changes` 응답의 `subscription`(끊김 감지 한 줄, [notion-webhook-sync.md](notion-webhook-sync.md) "구독 끊김 알아채기")이 `down`이면 한 줄 → 누르면 안내 창(이유 · 지금 몇 분마다 맞추는지 · 할 일). 돌아오면 저절로 사라진다.

## 되돌리는 법

- 앱만: 주소에 `?refresh=0`(신호 · 따라잡기 · 끼우기 끔, 요청 상태 표시는 남음) 또는 `hada-admin.html`에서 `liverefresh.js` 줄을 뺀다.
- 서버: `drop trigger app_rows_live_ins / app_rows_live_upd / app_rows_live_del on public.app_rows;` 와 `cr_*` 4표마다 `<표>_live_ins / _live_upd / _live_del`. 사본 쓰기와 무관하고, 앱은 60초 따라잡기로 계속 동작한다.
